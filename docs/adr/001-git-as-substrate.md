# ADR 001: Git as the substrate

**Status.** Accepted.

## Context

The original design put the intelligence in a wiki (Confluence or Notion) and
used the skills to read and write it through an API. That design needed a
hand-built review queue, hand-built concurrency control, hand-built audit
trails, and a reconciliation mode to detect page identifiers drifting.

The largest single risk in it was write concurrency. Updates sent the full page
body after a read, with no version check in between. Anyone editing the page in
the wiki interface between the read and the write lost their work, and because
writes were full-body they lost everything rather than one field.

## Decision

Vendor pages, signals, assessments and the tier index are markdown files in a
private git repository. Git is the source of truth. Any wiki presence is a
read-only mirror generated by CI.

## Consequences

What this removes:

| Problem | Custom build | With git |
|---|---|---|
| Write concurrency | Hand-rolled version checks | Native conflict detection |
| Staged review | Build queue, diff, audit trail | A pull request |
| Governance | Convention | `CODEOWNERS` plus branch protection |
| Contract enforcement | Pre-write string scan in the skill | Required status check, unskippable |
| Audit trail | Build it | Commit history |
| Rollback | Did not exist | `git revert` |
| Seed preview | Build a dry-run mode | A branch and a diff |
| Identifier drift | Build a reconcile mode | No identifiers to drift |
| Attribution | Store it, avoid memory | Commit authorship |

What it costs:

- Browsing is worse than a wiki. Accepted, because the consumption path is Claude
  and later an MCP server rather than a file browser.
- Search is weaker than Notion or Confluence native search, though grep across a
  corpus is better for what the skills need.
- No editing for non-technical contributors. Mitigated by the skill being the
  interface: a contributor runs `/competeupdate` and the skill opens the pull
  request. They never see git.
- The repository must be private, which is enforced in three places.

## Rejected alternative

A wiki mirror that is also writable. This reintroduces the concurrency problem
across two systems with no shared version space, which is worse than either
system alone. If a mirror exists, git is the only write path.

## What git does not solve

Three problems remain and are handled separately: confidence decay (a rendering
and gating rule), the descriptive and interpretive layer split (a content design
problem, see ADR 002 and the content contract), and ownership of the own-product
reference (a governance assignment).
